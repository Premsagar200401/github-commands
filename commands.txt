24> What is git rebase?

--> git rebase is used to move or reapply your commits on top of another branch
          “Take my changes and place them on top of latest code”

--> "git rebase is used to integrate changes by reapplying commits on top of another branch, resulting in a cleaner and linear commit history."

*****************************************
    without rebase only by using merge
*****************************************

     A---B---C (master)
         \
          D---E (feature)

-------------------------------------

     A---B---C------F (merge commit)
         \        /
          D------E

*******************************
    With rebase
*******************************

--> git checkout feature-login
--> git rebase master

     A---B---C---D'---E'
    
   * Cleaner history
   * No merge commit

*****************  Merge vs Rebase 🔥 (VERY IMPORTANT)  **********************************

           | Feature | Merge              | Rebase           |
           | ------- | ------------------ | ---------------- |
           | History | Complex            | Clean            |
           | Commit  | Adds merge commit  | No extra commit  |
           | Safe    | Safer              | Risky if misused |
           | Usage   | Team collaboration | Local cleanup    |
*******************************************************************************************

26> git reset --soft <commit_id>
-->
            What does it do?

--> It moves the HEAD (current branch pointer) to a previous commit
--> BUT keeps your changes in the staging area

👉 “Undo commit, but keep changes ready to commit again”

  Initial State:-
      
      A --- B --- C --- D (HEAD)

  Current branch is pointing to commit D

**** git reset --soft B ****

 after this:- 
            
---->  A --- B (HEAD)

------> HEAD moves from D → B
------> Commits C and D are removed from history

👉 Changes from commits C and D are NOT deleted

✔ They are moved to staging area

27> git reset --hard <commit_id>

--> It moves HEAD to a specific commit AND deletes all changes after that

👉 “Go back to that commit and delete everything after it”


Initial state:
A --- B --- C --- D (HEAD)

git reset --hard B 

after this ---->

A --- B (HEAD)

❌ Commits C and D are completely deleted
❌ Their changes are also removed

🔹 When do we use it?

👉 Only when:

--> You want to completely discard changes

--> You made a mistake and want to go back

--> Local changes are not needed

instead we use **** git revert <commit_id> ****


**************************************************************
✅ Use git reset

--> Local changes only

--> Not pushed to remote

--> You want to clean history

✅ Use git revert

--> Code already pushed to GitHub

--> Working in a team

--> Want safe undo
